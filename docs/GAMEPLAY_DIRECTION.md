# 守望梦屿玩法方向

> 状态：已确认。领域词汇以根目录 `CONTEXT.md` 为准，技术实施顺序见 `docs/DEVELOPMENT_ROADMAP.md`。

## 产品定义

守望梦屿是一个长期保存的多人合作生存剧情 SMP：世界有作者，玩家没有剧本。玩家可以自由建造、生存与社交，也可以从丧尸枪战、探索、线索讨论和身份合作中推动共同历史。

核心循环是：

1. 在驻地生存、建设并准备物资。
2. 参加探索或局部尸潮，在战斗中取得物资与线索。
3. 把个人发现自愿分享至公共调查板。
4. 玩家自由讨论并发起投票，形成可能正确也可能错误的社区结论。
5. 服主根据真实讨论修改服务端 JSON，通过热重载让 NPC 与广播作出回应。
6. 世界继续产生新事件、证据与共同记忆，并写入服务器年表。

## 不可违背的体验边界

- 不追主线的玩家仍能完整进行自由生存、建筑与社区活动。
- 枪械与尸潮服务于生存压力、共同事件和线索发现，不独立发展成纯刷怪副本。
- 幸存者与感染者采用软身份差异，基础建造、枪械与生存能力共享。
- 不稳定感染者才持续传播；稳定感染者可安全共处，但可能短暂传播复发。
- 真结局要求终局中的幸存者与稳定感染者完成不可替代的协作；净化与同化两个极端都失败。
- 感染者能够稳定是第一层反转，全员感染同样不完整是第二层反转。
- 错误社区结论能够继续推动内容，不由系统弹出标准答案。
- NPC只能被剧情杀，玩家流弹与技术事故不能永久删除角色。
- 世界阶段、建筑、关系、历史和结局长期保留，正式服不以清档重跑故事。
- 单人可以调查和准备，两名身份互补的在线玩家可以完成所有关键合作，多人动态扩展。

## 当前明确不改

- 正式版本为 Minecraft Forge 1.20.1。
- 重生点数恰好扣至 0 时本次仍能复活，下一次死亡才因点数不足被封禁。
- 半成品客户端任务完成能力暂时保留，但只能写入个人兼容记录，不能结束全服阶段任务或切换世界阶段。
- 当前死亡消耗、感染速度、接触范围、虚弱期等硬编码数值暂不迁移配置；先验证玩法闭环。

## 阶段任务与终端引导

- 阶段任务随服主发布的运营轮次存在于世界，玩家不必先接取，提前探索也能完成。
- NPC对话中的少量可行动信息可以红色加粗并写入玩家终端；强调不能标记线索真假或剧情结论。
- 终端同时显示全服已结束任务覆盖率与玩家个人在场覆盖率，只统计当前已经发布的阶段任务。
- 任务成功或正常失败都计入进度；失败不可正常重开并使用红色状态保留，具体代价由任务内容定义。
- 多人任务结束瞬间，任务区域内的生存或冒险模式玩家共同取得个人记录，不计算伤害、治疗或最后一击贡献。
- 玩家可以自由讨论和投票，任何投票都不是系统指定的阶段钥匙；服主随时根据真实讨论发布运营轮次和切换故事阶段。

## 第一条可玩纵切片

第一版不制作完整四阶段，而是完成“余梦末期进入管制期”的多人闭环：

1. 两名玩家在官方测试驻地进行普通生存。
2. 玩家从废墟、NPC或一次小型尸潮分别取得相互矛盾的线索。
3. 第一名真人玩家成为不稳定感染者，出现接触暴露与虚弱期。
4. 感染者稳定后，玩家能观察到传播状态变化，但暂时不能得出最终真相。
5. 玩家把线索复制到公共调查板，自由讨论并发起一次社区投票。
6. 投票结束后进入运营轮次，服主修改 NPC 与广播 JSON 并热重载。
7. 回应内容开放一次官方地点的局部剧情尸潮或验证行动。
8. 任务结束时场地内的参与者分别获得个人任务记录，并按具体内容取得新线索。
9. 服主依据已验证世界事实和玩家讨论发布管制期，并把事件写入服务器年表底层日志。

这条纵切片跑通前，不制作完整疑光期、破晓期、玩家领地场地和最终结局演出。
