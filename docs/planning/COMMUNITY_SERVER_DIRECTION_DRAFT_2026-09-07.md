# 守望梦屿：长期社区与剧情运营讨论稿

状态：2026-09-07 讨论稿，尚未确认为实施方案。本文不修改已有世界事实、线上规则或当前开发范围。

本稿结合服主反馈、原始设计、当前源码，以及本地客户端整合包 `D:/Desktop/mc/.minecraft/versions/DreamingFish-DreamingHaven-1.21.1/mods` 中的 115 个文件。客户端文件存在不等于正式服已启用全部能力；配方、配置、经济和装备平衡仍需要单独核查。截图是一位玩家的建议，不能替代不参与剧情的玩家意见。

## 1. 当前判断

服主反馈同时出现了装备毕业、自动化后资源过剩、普通丧尸缺乏威胁、缺少共同目标，以及部分玩家不关心主线。感染和模板重建余量被部分玩家理解为故意拖慢进度的负担。

因此需要同时处理四件事：

- 让基础生存和社交在没有剧情更新时也成立。
- 为已经掌握生产和战斗能力的人提供新的用途与目标。
- 为新玩家保留可理解、可恢复、可融入的体验。
- 让作者剧情与可重复活动、玩家自己的项目共同支撑运营。

现有两个阶段可作为世界历史与接入基础保留。后续可以恢复原稿的主题、人物与阶梯式反转，但不直接恢复所有旧技术方案和旧数值。原稿中仍有 Forge 1.20.1、旧治疗疗程和旧死亡规则等过期描述，本次讨论基于 NeoForge 1.21.1 的实际实现。

建议的产品承诺：**在一个长期保存的世界里，玩家经营自己的生活，与别人完成值得记住的事情；危机带来新的行动和选择，建筑、关系与贡献持续有价值。**

装备毕业可以成为开始经营项目、创造作品与参与远征的节点。玩家每周是否主动回来做自己想做的事情，比被维护任务迫使在线多久更值得关注。

## 2. 首先重审感染与重生

当前源码中，幸存者标准重建基础消耗为 5，感染者为 20；余量不足时允许扣尽完成最后一次。医院维护每次提交 2 个普通金苹果补充 5 点，每个主世界游戏日一次。补回感染者一次足额标准重建的消耗，需要四次维护、共八个普通金苹果。二级感染尚无现成的药物治疗出口。

完整的感染身份收益与后续医学内容尚未上线，玩家已经承受传播、负面效果和死亡代价。增加解释文字无法独自补足这种体验。

优先讨论的改版方向：

1. 普通 PvE 死亡不再通过封禁切断玩家参与社区的资格。模板余量可以影响现场重建、装备回收或恢复效率，耗尽时仍有医院提供的基本恢复路径。
2. 死亡成本保持明确、有限、可恢复；避免同时叠加尸体回收、永久能力损失、长时间等待、昂贵材料与登录限制。
3. 同伴救援提供便利和共同经历；无人在线时仍能选择自助恢复，不把玩家锁在等待别人救援的状态。
4. 二级感染需要可用的稳定或治疗路径。基础恢复不依赖通关主线、组织身份、另一名特定玩家或付出不可恢复的损失。
5. 临床分类、传播表现、效果图标与 NPC 指引保持一致。能够安全共处的状态必须实际实现，不能只靠对白宣称稳定。
6. 聚居地的安全相处应有可理解的保障。防护失效不应在居民离线或短暂停服维护时突然造成全社区感染。

这些属于需要服主另行确认的规则调整，本稿没有修改现有消耗或领取规则。

建议公开承认玩法调整是对实际体验的改进。世界观文案可以补充新的医疗安排，但不应借剧情掩盖平衡变化，也不应把玩家不喜欢机制归咎于没有认真阅读。

## 3. 对截图建议的取舍

| 玩家建议 | 建议处理 | 原因与落实方式 |
| --- | --- | --- |
| 小事件与大事件交替 | 采用 | 日常有变化，重要事件有铺垫、行动和事后回应；为玩家留出经营与庆祝的平静时间 |
| 丧尸突袭、异变与特殊感染者 | 有边界地采用 | 提前可观察、有应对方式，先用于官方任务地点或自愿登记场地 |
| 资源断链、灾后重建 | 改为公共任务目标 | 影响某条前线运输线、临时营地或公共设施的服务，不随机销毁玩家生产线和私人仓库 |
| 母巢、内鬼、零号病人 | 按原主线筛选 | 这些名称不是已确认世界事实；组织冲突应保留原稿的多种立场，不能用一个内鬼解释所有问题 |
| 按入住人口维持社区 | 改成按服务规模运行 | 不因接纳新人或存在离线居民而增加全体负担；先做能带来实际便利的可选服务升级 |
| 本周目作为下一周目前传 | 保留历史，延伸篇章 | 当前世界和建筑直接成为后续的历史，不把已经投入的世界降格为待放弃测试档 |
| 倒地与呼叫救援 | 值得做 | 保留自助退出等待与基本恢复方案，救援不依赖被救者永久牺牲成长 |
| 死亡降低生命上限，再由别人抽血制作药物 | 不直接采用 | 容易形成越弱越死、越死越弱的循环；把生存资格交给少数强者也可能加剧排斥和替代账号刷取 |

平衡审查应先确认玩家实际使用的毕业组合。安装包中存在高效率应力引擎、护盾装备和名为无限不死图腾的条目，但尚未验证其线上可获取性、实际效果与玩家持有情况，不能据此直接判定或移除某个模组。

## 5. 日常社区如何形成

以目前十多名活跃玩家的规模，先集中建设一个主要生活中心，并围绕实际项目组织小组。过早建立大量阵营、城市和硬职业会分散相遇机会，也容易让某项服务因为负责人不在线而停止。

每个玩家应容易找到三个入口：

- 我可以在这里住下、展示自己的作品或经营服务。
- 我知道现在谁需要帮助、有什么项目正在进行。
- 我知道本周有哪件可以和别人一起参加的事情。

建议第一批社区项目：

1. **医院周边生活区**：新人住宅、接待告示、公共工坊和小型市场。基础医疗和基本居住资格不交给玩家投票剥夺。
2. **公共交通与救援机库**：自愿认领建设、试飞、路线勘察和运送任务；作品可以投入实际使用并记录作者。
3. **社区项目栏**：求购、工程招募、教学、组队和活动。优先利用已有市场与消息工具验证需求，再决定界面开发。
4. **公共档案与展览**：保存建成的医院、第一次成功行动、玩家照片、报纸和线索副本。分享线索保留个人原件，摘要与具体证据区分。

角色应来自实际贡献：会修设备的人、组织远征的人、经营餐馆的人、记录故事的人。头衔可以提供展示与项目管理便利，不授予压制其他居民的权力。小贡献也应获得署名，不只表彰最高伤害、最大捐款或最长在线。

新玩家可以获得安全住处、基本装备、当前世界摘要和一次共同活动邀请。老玩家帮助新人时，鼓励一起体验和解释操作，保留新人亲手完成目标的机会。不要用无限带新奖励把接待变成刷号收益。

## 6. 老玩家的成长与可选择的危险

长期目标可以从个人装备扩展到制造更好的作品、经营可靠的服务、掌握新用途、探索新的场景，以及留下共同历史。设计上需要处理无限产出和实际漏洞，但正常自动化成果应得到用途与尊重。

建议划分生活、探索、远征三种体验：

| 场景 | 玩家预期 | 适合的挑战 |
| --- | --- | --- |
| 居住与公共生活中心 | 可以经营、社交与建设 | 有限基础风险；重要安全服务稳定可用 |
| 城郊与普通探索 | 可以准备、观察、避开和撤退 | 可识别的怪物组合、路线选择、有限资源压力 |
| 官方前线与自愿参加的行动 | 明确接受较高风险 | 特殊敌人、污染、多个现场目标、撤离与有限任务资产损失 |

新人保护不要只依赖等级：建造升级、赠送装备和进入服务器的时间不能准确代表对机制的熟悉程度。优先通过安全接入区域、清楚的危险预告、可选择的进阶行动与新人恢复保障来帮助融入。

战斗挑战应增加决策。例如需要压制干扰源、保护维修窗口、寻找撤离路线，而不是只给普通丧尸增加血量。重武器应有擅长发挥的目标，也有需要其他行动配合的场景。规模控制按实际参加行动的人数与已选难度，不让路过的高手突然把新人区域推成高难度。

明确不建议为了等待开发而安排灾难销毁私人进度。破坏性剧情如确有内容价值，应使用预先说明的官方设施、临时前线资产或明确授权的场地，具有预告、应对、损失上限和恢复方法。玩家没有上线不能成为其家园被剧情摧毁的原因。

长期可以采用“永久居住世界与历史 + 分篇章开放的官方行动区域”。将来如需刷新资源或挑战场景，只能作用于事先明确用途与边界的区域，不能波及后来被玩家建设和长期使用的地方。

## 7. 经济与维护不能成为新的负担

先审计货币来源、NPC 收购与售卖、自动化产出、玩家求购和高频支出。重复增加材料需求无法保证形成交易；无限收购自动化产物反而可能使资产差距继续扩大。

建议公共项目具有有限目标与真实产出：运力提升、开放新路线、增加展览空间、建立新的服务。材料投入只是其中一部分，现场建设、勘察、调试和运营同样产生价值。

社区维护优先用于可选的增强服务，如前线仓储、便捷运输或增益储备。基础住房、聊天、基本恢复和已建成建筑不应因漏交一日材料而失效。允许储备和多人异步分担；居民离线不产生无限欠费，人口增加不自动成为排斥新人的理由。

10 人社区暂不需要复杂税制和竞争性城市治理。先观察玩家是否真的需要交易、合作和共享设施，再增加长期制度。

## 8. 主线恢复与内容供给

保留原稿的两条冲突线：医学资料逐渐证明感染结果存在差异；外缘救援承诺在后续管制中受到考验。逐光会早期的帮助应真实有效，江晚与白芷的分歧有各自理由。后期再逐步呈现稳定感染与污染适应，以及“全员感染也不能独立解决重建问题”的第二层反转。

基础机制的使用说明要对所有人直接可见。普通参与者只需知道当前发生什么、可以做什么、可能损失什么；完整原理、人物动机和争议放在可选的交谈与证据调查中。不要把治疗和参与公共服务的资格绑定到通读故事。

主线仍可沿用已确定的规则：个人线完成达到固定人数后开放共同世界任务，由服主手动发布阶段或重大结果。不要求所有玩家跑相同的旧章节，也不强迫不看剧情的人参与投票。

运营内容需要三种来源共同支撑：

- **作者篇章**：不可重复的主线事实、人物发展和关键选择。
- **可重复活动**：巡查、维护行动、样本运输、防守等，具有有限变体、冷却与清楚的奖励规则；不重复上演同一次历史事件。
- **玩家项目**：建造、交易、教学、竞赛、报纸、机库开放日等，可以在主线更新间自然持续。

建议首先制作完整样章《重新接通的中继站》：

1. 医院发现部分交接资料缺失，同时外缘中继站报告设备故障。
2. 居民分别准备运输、修复材料、载具、火力或记录工具，按意愿参与。
3. 玩家完成路线勘察与现场恢复，在官方地点经历有预告的有限防守。
4. 现场各类有效参与者分别获得调查机会，普通战利品与永久剧情发现分开结算。
5. 中继恢复后，通信与后续行动确实可用；返回的病例资料与梁朔的断续呼叫成为新的线索。
6. 社区可以整理证据并讨论，医院与逐光会在下一轮发布回应，行动留下署名和可回看的历史。

这只是样章提案，不是已确认剧情。样章应覆盖“平静准备—异常预告—行动压力—结果与庆祝—新疑问”的节奏。它完成后留下一个可继续使用的场所与活动入口，才能在首次主线体验结束后继续发挥作用。

## 9. 开发投入与这一周的安排

愿意提高开发投入，可以用于交互质量、事件恢复、运营工具、完整内容和验证。仍需要控制同时开发的系统数量，因为设计与测试产能也有限。

建议依次完成：

1. **基础体验修复**：确定感染与重生的新边界，清晰反馈、实际恢复出口、新人接入。
2. **内容制作与验证基础**：指定线索、条件对话、事件模板、运营预览、进度诊断、重启恢复和可重复测试入口。
3. **完整样章**：把一轮准备、行动、证据、回应和共同成果做完，并让现有玩家实际体验。
4. **社区扩展**：根据真实使用需求增加项目栏、档案、服务管理和更复杂活动。
5. **后续人物篇章**：在上述能力可用后扩展管制期、疑光期与终局。

这一周适合作为体验修复和样章制作周期，同时给线上玩家保留自由建设与可选的轻量活动。优先整理毕业装备与资源来源、开放公共项目征集、收集实际挫败场景。不要要求玩家用无休止维护任务替代缺少新内容。

发布节奏应根据实际完成速度决定。可以把每周一次可选社区聚会作为试行节奏；主线按完成度与玩家讨论发布，争取保留下一轮可发布内容作为缓冲。两到四周一轮主线只能作为初始讨论范围，不能视为已经承诺的产能。

## 10. 宣传与新玩家留存

宣传素材应展示已可体验的载具、社区建筑、共同行动、调查与人物，说明自由生存和不追剧情也能参与。未完成的最终反转和大型灾难不能作为已经上线的承诺。

正式宣传前至少验证：

- 全新账号进入已经推进的世界，有当前摘要、住处、基础说明与可执行目标。
- 不看长篇剧情、没有麦克风的玩家也能正常使用医疗、市场和活动入口。
- 普通死亡与二级感染不会把新人困在无法恢复的状态。
- 一次完整活动可以可靠开始、结束、结算，并处理重连和中途退出。
- 现实场景中多人、载具、枪械与怪物同时出现时，服务器能承受计划的活动规模。
- 服主不在线时，有清楚的求助入口和处理规则。

先邀请少量新玩家试住，再发布宣传片扩大招募，观察他们实际停在哪一步。入服人数增加本身不能证明社区已形成。

建议每周简单记录人数与具体原因，而不是对十几人样本追求精确百分比：新玩家再次回来的人数、主动共同项目的参与人数、非剧情玩家参加活动的情况、因感染或死亡放弃行动的案例，以及一次活动需要管理员干预的次数。也要询问短暂停玩的人，是否仍愿意在下一次活动回来。
