# 尸潮区域与刷怪箱

> 相关决策：[ADR 0042](../../adr/0042-horde-areas-are-a-location-flag.md)（尸潮区域是地点开关而不是新地点模式）、
> [ADR 0032](../../adr/0032-task-locations-are-story-owned-regions.md)（任务地点是故事系统专用区域）、
> [ADR 0035](../../adr/0035-buildable-story-locations-use-economy-territories.md)（可建造地点叠加经济领地）、
> [ADR 0015](../../adr/0015-story-horde-clues-are-shared-by-contributors.md)（尸潮线索发给有效参与者）
>
> 地点本身的基础规则见 [任务地点系统](TASK_LOCATION_SYSTEM.md)。

## 一、尸潮区域

**尸潮区域 = 开着「尸潮」开关的任务地点。** 它不是第三种地点模式：保护规则、圈地规则、
进入提示与 HUD 全部沿用原模式，只是多了一个"这个区域允许刷怪箱工作"的属性。

```json
{
  "id": "dreamingfishcore:location_xxx",
  "name": "废弃医院尸潮区",
  "mode": "BUILDABLE",
  "horde": true
}
```

- 旧配置没有 `horde` 字段时默认 `false`，不会让现有地点突然开始刷怪。
- 开关与模式解耦：可建造地点（能圈地建造）与强制保护地点（玩家被迫冒险模式）都能开，
  服主按玩法挑。
- 命令切换（3 级权限，改完立刻落盘）：

```text
/dreamingfish task_location horde on <地点名>
/dreamingfish task_location horde off <地点名>
/dreamingfish task_location list          # 已开启的地点会显示「尸潮区域」
```

### 只放行刷怪箱的生成

任务地点内的**自动刷怪默认是被禁的**（避免剧情场景里野生刷怪）。尸潮区域把这条禁令
**只对刷怪箱来源（`MobSpawnType.SPAWNER`）放行**：自然刷怪与僵尸增援仍然被拦。
这样"开一个尸潮区域"不会顺带把整片地变成野生刷怪区。

## 二、刷怪箱

方块 `dreamingfishcore:spawner`，4 套外观，工作时发光。配置与运行状态**不放在方块实体里**，
而是按坐标存在世界存档的登记表 `<world>/data/dreamingfishcore/spawners.json`：
服务端要一次性遍历全部刷怪箱做周期判定，方块实体只能靠扫描已加载区块枚举。

### 交互

| 操作 | 效果 |
| --- | --- |
| 普通右键（有编辑权限） | 打开配置界面（创造模式或 2 级权限） |
| 普通右键（无编辑权限） | 聊天栏显示完整参数、当前状态，以及"为什么不在尸潮区域内" |
| 界面里的「换外观」按钮 | 循环切换外观（4 套） |
| 界面里的「确认」 | 提交正在编辑的那一格并关闭界面 |

**为什么用普通右键而不是"潜行 + 右键"**：原版在潜行且手持物品时会跳过方块交互去放手里的方块
（`MultiPlayerGameMode#performUseItemOn` 的 `isSecondaryUseActive` 分支），所以"潜行 + 右键开界面"
在手拿方块时根本不触发，玩家会以为界面打不开。换外观也因此从"创造模式右键"挪进了界面按钮。

红石信号会同步到方块状态，服主可以直接看出"是不是被红石卡住了"。

### 配置项

| 项 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| 刷的怪 | `dreamingfishcore:siege_zombie` | 任意实体 id | 界面里可直接输入，另附常用预设 |
| 检测范围 | 32 格 | 4–128 | 判定"附近有没有合格玩家"的水平半径 |
| 刷怪半径 | 8 格 | 1–64 | 以刷怪箱为中心的随机落点半径 |
| 每批数量 | 3 | 1–32 | 一批刷几只 |
| 刷怪冷却 | 600 tick（30 秒） | 20–24000 | **从上一批全部死亡开始计时** |
| 批次 | 3 | 1–64 | 一共刷几批 |
| 红石控制 | 关 | — | 开启后必须持续有红石信号才工作 |
| 剿灭自毁 | 关 | — | 开启后剿灭结算完就自我销毁 |
| 固定线索 | 关 | — | 开启后在剿灭结算时给区域内合格玩家各发一条线索 |
| 线索编号 | 0（不发放） | ≥0 | 线索的旧整数编号（见 `clues.json` 里的 `legacyId`），界面填编号即可 |
| 奖励经验 | 0 | ≥0 | 走本模组的等级系统 |
| 奖励梦鱼币 | 0 | ≥0 | 走 EconomySystem 入账 |
| 奖励物品 | 空 | ≤16 条，每条 ≤64 | 背包塞不下就掉在脚下 |

所有数值由**服务端**夹取：客户端提交的任何内容都当作不可信输入。

### 启用条件

三者同时满足才工作（方块状态显示为"工作中"）：

1. 位于**开启尸潮开关**的任务地点内；
2. 检测范围内有**生存或冒险模式**玩家（创造与旁观不算，服主可以从天上布置）；
3. 勾了红石控制时，必须持续有红石信号。

### 刷怪节奏

- 全新的一台在首次启用时**立刻**刷第一批；
- 之后每一批都要等**上一批全部死亡**才开始计冷却，冷却到了再刷下一批；
- 批次刷满且场上清空 = **剿灭达成**。

### 剿灭结算

结算瞬间给**区域内**的生存/冒险玩家发奖励（与任务地点结算口径一致：按在场，不按最后一击）。
**每台刷怪箱对每个玩家只发一次**，跨轮次保留；不自毁的刷怪箱会等一个冷却后重开一轮，
所以它可以反复用来做活动，但不能反复领奖。

## 三、常见问题：界面显示「不在尸潮区域内」

任务地点是**三维**盒子：`contains()` 同时判定 X、Y、Z。这一点与 EconomySystem 的私人领地不同
（领地只看 X/Z，权限贯穿整列），**不要混用**。

最常见的原因是区域**只有一格高**：用两个同 Y 的角点划出来的区域，Y 范围就是一个平面，
刷怪箱放高或放低一格就落在区域外。

界面（以及右键看状态时的聊天栏）会直接给出原因，不用猜：

| 提示 | 含义与做法 |
| --- | --- |
| 位置在尸潮区域「X」的 X/Z 范围内，但高度超出（区域 Y a..b，当前 Y c） | 挪到该高度，或把区域重新划高（建议上下各留几格） |
| 位置在任务地点「X」内，但它没有开启尸潮开关（/dreamingfish task_location horde on X） | 按提示开开关 |
| 当前位置不在任何任务地点内：刷怪箱必须放在开启尸潮开关的地点里 | 把刷怪箱放进区域 |

两个相关提醒：

- **重新划范围（`select` + `confirm`）会重建地点定义，尸潮开关会被重置为关闭**，需要再执行一次 `horde on`。
- `horde on` 开启时，如果该区域不足 5 格高，命令会一并给出"只有 N 格高"的提醒；
  也可以用 `/dreamingfish task_location pos1 <x> <y> <z>` / `pos2 ...` 直接填坐标把区域划高。

## 四、边界与注意事项

- 刷怪箱**只有在区块加载时**才判定：区块没加载就整台暂停（不推进批次、也不结算），
  避免把"读不到的实体"误判成"已清理"。
- 追蹤的生成物如果跑远到区块卸载，会被当作已消失（原版没有"这个 UUID 存在但未加载"的查询接口）。
  检测范围本身要求玩家在场，正常玩法下不会触发。
- 落点会上下找 3 格，找一个"脚下有实体方块、上方两格可站"的位置；找不到就少刷一只，
  不会把怪刷进墙里。
- 尸潮区域**不改变**保护与圈地规则；TNT/岩浆/打火石的限制仍按地点模式执行。
- 剧情尸潮的线索应发给**有效参与者**（ADR 0015）。本功能的固定线索按"结算时在场"发放，
  比 ADR 0015 的贡献口径更宽松；需要严格按贡献时应当由剧情脚本另行结算，而不是靠刷怪箱。

## 五、验证

- 单测：刷怪箱默认值与两级夹取、坏 JSON 修复幂等、批次调度（立刻开刷 / 等清场 / 等冷却 /
  轮次冷却）、奖励记账（每台每人一次、跨轮次保留）、检测半径与落点不越界。
- 无头 gametest：`spawnerSpawnsABatchAndSettlesRewardsWhenCleared` —— 真实结构里建尸潮区域、
  放刷怪箱、放一名生存玩家，验证"刷出一批 → 清场 → 结算奖励"，并跑一次快照编解码往返。
  该测试会**备份并恢复** `run/config/dreamingfishcore/task_locations.json`（gametest 与开发客户端
  共用这份配置）。
- 实机：尚未在真人环境完整跑过（配置界面、外观切换、红石联动、自毁）。
