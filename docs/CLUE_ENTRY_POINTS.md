# 线索发放入口

> 里程碑 2 的六种入口：**方块、容器、NPC、区域、广播、事件**。
> 声明写在服主私密文件 `config/dreamingfishcore/clue_secrets.json` 的 `grantSources` 里，
> 代码只认格式，不认识任何一条线索的名字。
>
> 相关：[ADR 0008](adr/0008-clues-require-cross-validation.md)（线索需要交叉验证）、
> [07-丧尸线索掉落文案](../../PROJECT-M.D.G.A/docs/story/07-丧尸线索掉落文案.md)（内容侧）

## 一、声明写在哪

```json
[
  {
    "id": "dreamingfishcore:clue/example_clue",
    "authorStance": "……",
    "evidencePackId": "pack.example",
    "claimId": "claim.example",
    "relation": "support",
    "truthNote": "……",
    "relatedClueIds": [],
    "alternativeClueIds": [],
    "grantSources": ["container=minecraft:chest", "event=hospital_review"]
  }
]
```

- `grantSources` 是**字符串数组**，一条线索可以同时挂多个入口（玩家从哪条路走到它都算数）。
- 文件缺失 = 所有入口都不发东西，**不影响保底通道**（见第四节）。
- 私密文件**只在服务器上**：它含有 `truthNote` 这类真相字段，写进模组资源等于把答案随 jar 发给每个客户端。

## 二、六种入口

| 声明写法 | 触发时机 | 键是什么 |
| --- | --- | --- |
| `block=<方块 ID>` | 玩家**挖掉**该方块 | 命名空间 ID，如 `dreamingfishcore:settlement_filter` |
| `container=<方块 ID>` | 玩家**右键打开**该容器 | 命名空间 ID，如 `minecraft:chest` |
| `npc=<NPC 编号>` | 与该 NPC 的对话界面**打开后** | 十进制编号，如 `106` |
| `area=<地点名或 ID>` | **真正进入**该任务地点时 | 地点名称（`阿拜多斯区域`）或稳定 ID 都可以 |
| `broadcast=<公告 key>` | 玩家**读完**该公告 | 公告的 `key`，如 `hospital.opened` |
| `event=<事件键>` | 剧情代码在对应位置**主动触发** | 见第三节 |

写法的硬性要求（不满足会被加载期拒掉并记警告）：

- 前缀必须是上表六个之一，小写，`=` 前后不要有多余空格（键本身会自动 trim）。
- `block=` / `container=` 的键必须是 `命名空间:路径` 形状，且全是小写字母、数字、`_`、`.`、`-`、`/`。
- `npc=` 的键必须是**数字**——写成名字的话永远匹配不上，不如直接报错。
- 键最长 128 字符。

## 三、可用的剧情事件键

事件键由 Java 在剧情流程里触发，服主只用它来挂线索：

| 事件键 | 触发位置 | 说明 |
| --- | --- | --- |
| `hospital_review` | `HospitalStory.review()` | 玩家完成医院第一次正式复查 |

> 新增事件键时要同时在代码和本表登记。事件触发点是"这里发生了一件有名字的事"，
> 不带任何线索信息——挂什么由 `grantSources` 决定。

## 四、和"保底通道"的关系

关键线索（`01 / 04 / 11`）另外有一条**保底通道** `ClueGuaranteeService`：医院复查、疗程终检、
感染者标准重建、刷怪箱剿灭各发一张。它**不走 `grantSources`**，理由是这四条属于"没拿到就断线"
的关键内容，不能因为服主没配私密文件就失效。

两条通道**互不干扰、都幂等**：同一条线索无论从哪条路先拿到，另一条都会自动跳过。

## 五、加载与排查

启动日志会打出索引规模：

```
线索目录加载完成：12 条（其中 12 条带旧编号，私密定义 4 条，发放入口 5 个）
```

- `发放入口 N 个` = 索引里有多少个不同的 `类型:键` 组合（0 个说明 `grantSources` 全是空的或都写错了）。
- 单条声明写错**只会跳过它自己**，并在日志里给出原因：

```
线索发放入口声明非法，已跳过：dreamingfishcore:clue/xxx → "chest=minecraft:chest"（合法前缀：block / container / npc / area / broadcast / event）
```

- 私密定义指向已删除的线索时同样只记警告：`线索私密定义指向不存在的线索，已忽略：…`
- 改完文件后重载：`/dreamingfish clue reload`（可见内容与私密定义一起重载）。
  可以先用 `/dreamingfish clue info` 看当前的条目数与入口数。

### 可达性审计

```text
/dreamingfish clue audit
```

把每条线索按"有没有玩家真的走得到的入口"分三类：

```text
线索可达性审计（12 条）
  声明入口 3 条：03 09 10
  保底通道 3 条：01 04 11
  仅随机掉落 6 条：02 05 06 07 08 12
  证据包 pack.personhood：4 条材料，其中 4 条可达（完整）
```

- **仅随机掉落**：只能靠 0.01% 掉落拿到。随机掉落是从**全池**里取还没收录的线索，所以这些
  线索并非永远拿不到，只是**没有确定途径**——想让人稳定拿到就得挂入口。
- **声明解析失败**：`grantSources` 里写了东西但解析不过（前缀拼错、方块键不是命名空间 ID、
  `npc=` 写了名字），会单独列出来。这种情况索引里没有它，但配置文件**看起来是写了**的，
  最容易误判成"配好了却没生效"。
- **证据包缺口**：某个包里出现"只能靠掉落"的材料时会标红——那个包的论证链就断了一环，
  而证据包恰恰是靠多来源互证成立的。
- 审计与索引**共用同一套解析判据**（`ClueGrantSource.hasValidDeclaration`），
  所以不会出现"审计说有入口、实际却没进索引"的偏差。

## 六、设计取舍

- **为什么不做模板自动生成**：私密文件含真相，自动写一份到服务器等于替服主做了内容决定；
  现在缺失就按"没有隐藏信息"运行。
- **为什么入口不做权限判定**：入口只回答"这件事发生了没有"，资格判定留给内容设计；
  想让某条线索只有会长能拿，应该挂在会长才会做的事上，而不是在入口里加权限。
- **`container=` 的判据是"右键的方块本身是容器"**，不用 `PlayerContainerEvent.Open`——
  后者拿到的是容器菜单，反查方块坐标更绕。
