# 余梦期医院小章：发布与单人验收

医院小章在服务器加载或进入“余梦期”时自动开放；已经处于余梦期的旧存档更新重启后也会接入，无需启动指令。医院建筑由服主现场验收，世界章节仍由服主控制。新常驻服务按已确认规则提供：**每人每个主世界游戏日提交 2 个普通金苹果，恢复 5 点模板重建余量，上限 100**。

## 玩家流程

| 顺序 | 内容 | 完成判定 |
| --- | --- | --- |
| 1 | 下一次醒来 | 打开终端剧情广播中的《生命模板与重建余量说明》 |
| 2 | 让医院有个地址 | 默认 3 名不同玩家读过说明后解锁；共同建设，由服主验收 |
| 3 | 第一次正式复查 | 医院开诊、本人读过说明、进入医院，向江晚选择“正式复查” |

说明由江晚署名，介绍模板保存的身体结构、神经连接、基础记忆、感染状态与定位信息，解释标准重建、保留物品、感染者消耗和模板维护。打开说明即记录阅读，不要求客户端滚动到底，也没有现实时间等待。

建设要求是接待区、治疗观察区、模板维护房间。建筑形式由玩家决定，脚本不检查方块、床位、电路或房间结构。人数门槛只负责开放建设任务，不能替代现场验收。建设者的个人参与名单不因验收或阅读公告被自动填写。

正式复查独立于旧的首次接待流程：二级感染者同样能完成复查，检查结果不伪造治愈、发药或面具领取。结果只在江晚的 NPC 对话框显示本人的感染状况与模板重建余量，不再追加通用的白芷随访备注或重复发送到聊天栏。继续交谈可返回江晚原有医疗流程。

## 配置与 NPC

首次加载生成 `config/dreamingfishcore/hospital.json`：

```json
{
  "schemaVersion": 1,
  "requiredPlayers": 3,
  "dailyItemId": "minecraft:golden_apple",
  "dailyItemCount": 2,
  "dailyRestorePoints": 5.0
}
```

数量范围 1–64，恢复量大于 0 且不超过 100，阅读人数范围 1–16384。物品按具体物品 ID 匹配；默认只收普通金苹果，不会把附魔金苹果当成普通金苹果。

新增 **NPC 106：医疗工作人员**。角色定义会补入缺失的 NPC 配置，不覆盖已有同编号档案。默认使用原版 Alex 外观，可通过 `npc_data.json` 的外观配置替换。

在准备好的临时接待位置执行：

```text
/npc spawn 106
```

打开界面只说明规则，不扣物品。玩家明确选择“提交并维护”后才从主背包和副手收取物资。满余量、材料不足或本日已领取时不会扣物，也不会凭失败操作消耗新的每日机会。99 点提交后只恢复到 100，仍按一次完整维护结算。

维护成功、材料不足、当天已办理等结果统一在医疗工作人员的对话框显示，不再发送聊天消息；默认材料显示为“普通金苹果”。读完后继续交谈可返回规则和最新余量，失败后也可直接再次选择“提交并维护”。结果只在当前 NPC 会话内保留，重新打开或退出服务器后清除。

服务在医院小章发布后即可于临时接待点办理，无需等待医院建成，也不要求入会、感染治愈、个人阅读或参与建设。医院建成后继续保留；以后切换章节也不会取消已开放的每日服务。

## 发布顺序

1. 准备临时接待 NPC，按需调整配置和文案；医院建筑和 NPC 位置仍需自行安排。
2. 更新并重启服务器。当前已是余梦期时，模板说明、个人阅读任务和每日维护会自动开放；第一阶段存档将在以后进入余梦期时开放。可选用以下命令查看状态：

   ```text
   /dreamingfish story hospital status
   ```

   重复启动会保留原有公告、阅读记录和医院进度。`hospital start` 保留为兼容的核对命令，正常流程无需执行。

3. 规划医院范围。使用现有地点工具，选取包含玩家站立位置和 NPC 的完整区域：

   ```text
   /dreamingfish task_location select buildable 阿拜多斯医院
   /dreamingfish task_location pos1
   /dreamingfish task_location pos2
   /dreamingfish task_location confirm
   /dreamingfish task_location info 阿拜多斯医院
   ```

   在两个角点分别执行 `pos1`、`pos2`。创建区域后还需将其绑定给医院剧情；支持地点名称或 `info` 输出中的稳定地点 ID：

   ```text
   /dreamingfish story hospital site 阿拜多斯医院
   ```

   名称必须与实际创建的地点一致；例如地点名为“阿拜多斯医院”时使用上面的命令。绑定后内部保存稳定 ID，不会因地点改名丢失绑定。此名称绑定能力需要更新服务端；旧版 `hospital site` 仅接受内部 ID。

4. 达到阅读人数后，建设任务与建设公告开放。玩家完成建筑，你现场确认房间与用途。
5. 把江晚和医疗工作人员安排到医院区域，再验收：

   ```text
   /dreamingfish story hospital complete
   ```

   只有已开放的建设任务和有效医院地点才能验收。任务结果先保存，随后发布开诊公告并开放正式复查。重复验收不会重复结算；章节仍是余梦期。

江晚原有的接待、试剂和面具引导会更新到医院位置，旧医疗接待点仍保留兼容。玩家尚未完成的基础医疗流程可以继续；医院世界任务不会强制跳过这些个人事实。

配置调整后执行：

```text
/dreamingfish story hospital reload
```

降低门槛后会重新检查；已开放的建设任务不会因提高门槛重新锁定。医院任务是内置剧情，不需要再写一份 `story_operations.json` 世界任务。

## 每日维护的日期与保存

- 统一使用主世界 `dayTime / 24000` 的游戏日期。睡觉进入下一天后可再次领取，下界或末地不会形成独立额度。
- 重启、重连和重复点击不会刷新额度。没有领取的日期不累积次数。
- 把世界时间往回调不能重复领取；日期需要超过最后领取日才能再领。开发测试用 `/time add 24000`，避免用 `/time set day` 倒退日期。
- 扣除物资时，付款收据与背包一起保存进玩家 NBT。确认付款落盘后，余量和每日记录一起写入属性文件。
- 保存中断时保留已付款申请，后续登录或再次点击会补齐，不再收第二份材料。已经入账的旧收据不会重复加点。
- 恢复未完成申请使用原付款日期和原恢复量，后续修改配置不会改写旧申请。

## 模板重建余量与旧规则修正

死亡界面、个人资料和相关帮助文字统一使用“模板重建余量”。原有属性存储字段保持兼容，不重置玩家余额。

此次同时修正实际死亡判定：**只要余量大于零，就允许最后一次标准重建；实际扣除不超过当前余量。余量已经耗尽之后的下一次死亡才进入死亡救援状态。** 幸存者和感染者的基础消耗保持原值；保留物品仍要求足额支付。界面剩余次数按这一规则向上取整。

二级感染者完成真实首次接待后，旧复核任务可以结束，停止生成不适用的服药引导。其治疗事实仍是未治愈，面具领取独立继续。

## 单人开发验收

在单独的开发存档把 `requiredPlayers` 改为 1，走同一条正式流程。正式服保留 3 或你需要的人数。

1. 第一阶段确认没有医院任务、工作人员不收物。进入余梦期后确认无需 `hospital start` 即出现说明与阅读任务；用尚未启动过医院小章的余梦期存档重启，也应自动接入。阅读说明后确认建设只解锁一次。
2. 材料不足时点击维护，确认对话框显示所需普通金苹果数量、余额和背包及每日机会不变，聊天栏不重复显示办理结果。准备 2 个普通金苹果后确认只收 2 个、恢复 5 点；结果在当前对话中显示，继续交谈返回规则和最新余量。重复点击与重连不重复收取或加点。
3. 推进一个主世界游戏日再领；重启后确认本日记录保留。余量为 100 时不扣物，接近 100 时只恢复到上限。
4. 没有绑定地点或建设未开放时，验收应被拒绝。绑定地点并验收后，到医院与江晚正式复查；在区域外操作不完成任务。
5. 用二级感染状态复查，确认任务可完成但感染等级不被清除；原面具和接待流程仍可继续。复查只显示本人检查结果与余量，不出现白芷的固定备注，聊天栏不重复发送；切换 NPC 后不串入上一位 NPC 的办理结果。
6. 在开发存档验证低于基础消耗但大于零的余量：标准重建可用、保留物品不可用，重建后余量为零。正式服不要用死亡来做这项验证。

自动化覆盖每日限领、跨日与回拨、封顶、重复收据、付款保存失败、属性保存失败后的重试、存档升级、真实任务记录、二级引导及剩余重建次数。实际 NPC 摆放、建筑区域和游戏画面仍需按上述步骤验收。
