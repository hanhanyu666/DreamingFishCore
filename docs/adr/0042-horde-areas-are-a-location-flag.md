# 尸潮区域是地点开关，不是新的地点模式

「尸潮区域」需要和可建造地点一样的保护与圈地规则，只是额外允许区域内的刷怪箱工作。我们把它做成任务地点上的一个布尔字段 `horde`，而不是第三种 `TaskLocationMode`。

原因是模式会渗透到所有按 mode 分支的地方：HUD 标签与配色、边界渲染颜色、圈地策略的三处过滤、命令解析与提示文案、选区通知、`ZombieTaskLocationRules` 的判定。新增一种模式意味着这二十多处都要同步改一遍，而其中任何一处漏改都会表现为"某些地方把尸潮区域当成强制保护区"这种难查的错。开关方案下，这些分支完全不用动：尸潮区域在它们眼里就是原来的模式。

同时定下三条配套规则：

1. **只豁免刷怪箱来源**：任务地点内的自动刷怪禁令只对 `MobSpawnType.SPAWNER` 放行，自然刷怪与增援仍然被拦。否则开一个尸潮区域会顺带把整片地变成野生刷怪区。
2. **旧配置默认关闭**：缺少 `horde` 字段视为 `false`，避免升级后现有地点突然开始刷怪。
3. **开关可运行时切换**：地点字段历来只能改 JSON 后热重载，`horde` 是第一个例外（有 3 级权限命令，改完立刻落盘，失败回滚）。刷怪开关是运营中随时要调的东西，逼服主改文件重启不合理。

代价是地点数据模型里多了一个只对特定玩法有意义的字段。相对"新增模式后必须记住改二十处"的风险，这个代价可以接受。
