# ADR-0001：世界故事推进由服务端状态决定

- 状态：接受
- 日期：2026-07-21

## 背景

现有故事任务系统仍是半成品，客户端可以提交任务完成请求。守望梦屿的新方向要求全服共享故事阶段，并根据感染事件、游戏时间、线索、NPC 关系、区域探索和公共行动推进。

如果世界阶段直接依赖客户端任务完成包，单个客户端就能跳过调查、提前开放区域或破坏全服进度。另一方面，完全删除现有任务系统会阻碍当前调试和 UI 开发。

## 决策

保留现有故事任务客户端完成能力，直到任务系统后续重做；但新增的世界阶段推进不得把客户端任务完成结果作为唯一权威依据。

世界故事由服务端持久化的 `WorldStoryState` 和服务端 `StoryDirector` 管理。可推进阶段的输入必须来自以下来源之一：

- 服务端 Forge 事件；
- 服务端验证过的世界交互；
- 服务端保存的时间与计数；
- 管理员命令；
- 经过服务端验证的公共行动结果。

任务完成记录可以作为展示、统计或某个条件的组成部分，但不能单独越过关键阶段门槛。

世界阶段与个人认知分开保存：世界阶段全服共享，不因新玩家加入或老玩家回归而倒退；个人认知记录玩家实际取得的线索。公共档案只提供理解当前局势所需的历史摘要，关键证据必须保留多个可重复取得的来源，避免一次性事件造成永久断线。

## 结果

### 正面影响

- 保留半成品系统用于调试，不阻断当前开发。
- 单个客户端不能直接改变全服阶段。
- 阶段可以在重启后恢复，并支持审计、回退和管理员干预。
- 后续可以逐步把任务系统迁移到统一条件/动作框架。

### 成本与风险

- 短期内会同时存在“任务完成记录”和“世界推进状态”两套概念。
- UI 必须明确区分个人任务、公共行动和世界阶段。
- 需要提供后来者追赶内容，但不能用自动解锁全部线索代替调查。
- 内容配置需要校验重复触发、阶段跳跃和无法满足的条件。

## 暂不处理

- 本 ADR 不要求现在删除或加固客户端故事任务完成包。
- 本 ADR 不改变重生点数恰好扣到 0 时仍可完成本次复活的规则。
- 本 ADR 不要求当前阶段立即把所有硬编码数值迁移到配置文件。
